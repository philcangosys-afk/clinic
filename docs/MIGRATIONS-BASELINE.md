# توحيد تاريخ الهجرات مع Supabase

## المشكلة

```
supabase → migrations: []
```

رغم أن كل الجداول والدوال موجودة فعلًا. السبب أن الهجرات طُبِّقت يدويًا من
محرّر SQL، فلم يُسجَّل شيء في `supabase_migrations.schema_migrations`.

ويزيد الأمر أن الملفات موزَّعة على مجلدين:

| المجلد | الملفات |
|---|---|
| `supabase/migrations/` | 0001 – 0012 |
| `migrations/` | 0013 – 0061 + ملفات `TASK2_*` (إصلاحات لمرة واحدة، ليست هجرات) |

وأسماء الملفات (`0001_…`) لا تطابق ما يتوقّعه الـCLI (`<14 رقمًا>_اسم.sql`)،
فحتى لو وُضعت كلها في المجلد الصحيح لتجاهلها `supabase db push`.

**الأثر:** إعادة إنشاء القاعدة أو نشرها في بيئة ثانية (تجريبية، أو نسخة
لعميل آخر) تصير عملية يدوية طويلة قابلة للخطأ — وترتيب واحد يُنسى يكسر
البقية.

## الحل الموصى به: خط أساس من قاعدة الإنتاج

لا تُعاد تسمية 56 ملفًا ولا يُعاد تشغيل شيء على الإنتاج. تُؤخذ **لقطة**
للحالة القائمة وتُعلَّم مطبَّقة، ويبدأ التاريخ الرسمي منها.

```powershell
cd D:\fusion-starter-108

# 1) تثبيت الـCLI (مرة واحدة)
npm install -g supabase

# 2) تهيئة المشروع وربطه
supabase init
supabase login
supabase link --project-ref rgzdvrluwbwoutvuejmz

# 3) أخرج الملفات القديمة من مجلد الهجرات حتى لا يلتقطها الـCLI
#    (تبقى في migrations\ سجلًّا تاريخيًا مقروءًا — لا تُحذف)
move supabase\migrations\*.sql migrations\

# 4) خط الأساس: لقطة مطابقة للإنتاج، تُعلَّم مطبَّقة تلقائيًا
supabase db pull

# 5) التحقق: يجب أن يقول "لا تغييرات"
supabase db push --dry-run
```

بعدها يصير أي تغيير جديد:

```powershell
supabase migration new add_something
# اكتب SQL في الملف الجديد
supabase db push
```

## لماذا لا نُعيد تسمية الملفات الـ56 ونرفعها؟

لأن `supabase db push` **يُشغِّل** كل هجرة غير مسجَّلة. وتسجيلها بلا تشغيل
يحتاج `supabase migration repair --status applied <version>` ستًّا وخمسين
مرة، وأي سطر يُنسى فيه يعني إعادة تشغيل هجرة على قاعدة حيّة. المخاطرة لا
تشتري شيئًا: التاريخ التفصيلي محفوظ في الملفات وفي `README.md` للقراءة
البشرية، والقاعدة لا تحتاج منه إلا نقطة بداية صحيحة.

## ملاحظة على ملفات `TASK2_*`

ليست هجرات: هي إصلاحات بيانات لمرة واحدة (نقل مواعيد وقعت تحت منشأة خاطئة،
ثم اعتماد قيود العزل). أُبقيت للتوثيق ولا يجوز إدراجها في أي مسار هجرات
تلقائي — تشغيلها على قاعدة نظيفة لا معنى له، وعلى قاعدة أخرى قد يُحرّك
بيانات لا تخصّها.
