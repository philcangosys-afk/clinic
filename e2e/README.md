# اختبارات الرحلة الكاملة

مشروع اختبار **منفصل** عن التطبيق. سبب الفصل عملي لا تنظيمي: إضافة
`@playwright/test` إلى `package.json` الجذري تُخلّ بـ`pnpm-lock.yaml`، وبناء
Netlify يعمل بقفل مجمَّد فيفشل. المجلد هنا له `package.json` خاص، ولا يلمسه
البناء إطلاقًا.

---

## ⚠️ لا تُشغَّل على بيانات الإنتاج

الاختبارات تُنشئ **مرضى ومواعيد وفواتير حقيقية**. لها مكانان فقط:

1. نسخة اختبار من المشروع، أو
2. **منشأة اختبار مخصَّصة** داخل نفس المشروع، بحسابات لا تخدم مرضى فعليين.

وبيانات مريض اختبار بين بيانات مرضى فعليين ليست فوضى فحسب: التذكيرات
ستُرسَل إلى أرقامهم.

---

## التشغيل

```bash
cd e2e
npm install
npm run install:browsers

cp .env.example .env      # ثم املأ القيم
npm test                  # كل الاختبارات
npm run test:journey      # الرحلة الأساسية وحدها
npm run test:headed       # بمتصفح ظاهر لمتابعة ما يحدث
npm run report            # تقرير HTML بعد التشغيل
```

### اختبارات القاعدة

منفصلة عن المتصفح، وتعمل **داخل معاملة تُلغى** فلا تترك صفًا واحدًا:

```bash
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f sql/db-guards.test.sql
```

تفحص ثمانية حراس: منع التداخل، منع القفز في الحالات، الحظر يمنع الحجز، حظر
الرسائل لا يمنع الحجز، رسالة المحظور تُسجَّل ملغاة، الوقت خارج الدوام مرفوض،
الوقت داخل الدوام مقبول، والخط الزمني يرفض مريضًا غير موجود.

## متغيّرات البيئة

| المتغيّر | الغرض |
|---|---|
| `E2E_BASE_URL` | عنوان نسخة الاختبار |
| `E2E_RECEPTION_EMAIL` / `_PASSWORD` | حساب موظف استقبال |
| `E2E_DOCTOR_EMAIL` / `_PASSWORD` | حساب طبيب |
| `E2E_ACCOUNTANT_EMAIL` / `_PASSWORD` | حساب محاسب |
| `E2E_MANAGER_EMAIL` / `_PASSWORD` | حساب مدير |
| `E2E_RUN_ID` | اختياري — معرّف الجولة (يُولَّد تلقائيًا) |

`.env` مُستثنى من git. لا تضع كلمات مرور في أي ملف يُدفع.

## التنظيف

كل مريض يُنشأ باسم يحمل `E2E_RUN_ID`، فالبحث عنه يكشف ما أنشأته الجولة
بالضبط. للحذف بعد جولة ناجحة، شغّل في محرّر SQL:

```sql
-- استبدل المعرّف بما طبعته الجولة
\set run_id 'E2ELXXXXXX'

delete from appointments a
 using patients p
 where p.id = a.patient_id and p.name_ar like '%' || :'run_id' || '%';

update patients set merged_into_id = null
 where name_ar like '%' || :'run_id' || '%';

delete from patients where name_ar like '%' || :'run_id' || '%';
```

الحذف بهذا الترتيب مقصود: المواعيد قبل المرضى، وإلا منعت القيود الأجنبية
الحذف.

## حدود هذه المجموعة — تُقرأ قبل الاعتماد عليها

**المحدِّدات (selectors) مكتوبة بالنصّ العربي الظاهر** (`getByRole` و
`getByLabel`)، وهي أثبت من محدِّدات CSS لكنها ليست معصومة: تغيير صياغة زرّ
يكسر الاختبار. **الجولة الأولى ستحتاج على الأرجح ضبط بعض المحدِّدات** — وهذا
متوقّع، لا عيب في المجموعة.

ولم أُشغّلها بنفسي: تشغيلها يحتاج تطبيقًا حيًّا وحسابات بأربعة أدوار
وكلمات مرور، ولا أتعامل مع كلمات المرور. أما **اختبارات القاعدة فشغّلتُها
فعلًا** وكل فحوصها الثمانية نجحت.

## ما تغطّيه

**`journey.spec.ts`** — الرحلة بأربعة أدوار: إنشاء مريض ← موعد ← تأكيد ←
وصول ← تسجيل ← نداء ← بدء زيارة ← (طبيب) شكوى وحفظ ← (محاسب) فاتورة ←
(استقبال) إنهاء ← التحقق من ظهور الأحداث في رحلة المريض وسجل التدقيق.
ومعه فحصٌ يمرّ على ست شاشات ويرفض أي خطأ `PGRST` أو `42P17` في الطرفية أو
طلب فاشل — وهذه أخطاء **لا تظهر إلا وقت التشغيل**، فلا يمسكها `tsc` ولا أي
فحص ثابت.

**`guards.spec.ts`** — منع الحجز المتداخل، إلزام سبب إعادة الجدولة، إلزام
سبب الإلغاء، منع حجز مريض محظور (بالرسالة الآتية **من القاعدة**)، إخفاء
الإجراء الإداري عمّن لا يملكه، منع زيارة ثانية لنفس الموعد، ومنع فتح موعد
منشأة أخرى بمعرّفه.
